# Agent 步骤超过 100 条后停更

## 证据

消息 `qgpnwas4klzuug4` 的步骤仍保存在数据库。按线上接口的 `revision` 顺序取前 100 条，
游标为 113，最后一个内容分段的更新时间为 `2026-11-17 10:52:51.261Z`。
19:16 手机截图显示“最近步骤：23 分钟前”，与这张第一页的时间吻合；查询时后面仍有 12 条记录。

`useAgentParts` 在 `hasMore=true` 时将轮询缩短到 100ms。
`useAsyncData` 未等待旧请求完成就再次调用 reload，而 reload 会 abort 前一次请求。
因此第二页的 RTT 超过 100ms 时会被反复取消；重新进入页面或刷新后，显示会退回第一页。
这是读取分页的问题，不能据此认为数据库里的后续步骤被删除。

## 修复

- 一次加载顺序读完所有增量页，再一起提交游标和合并后的 Map。
- 后页失败或加载被取消时，保留完整的上一次视图，重试从已确认游标开始。
- 自动轮询等待请求完成，不打断仍在加载的请求；清理组件时停止后续定时器。
- 合并时保留每个 key 的最新 revision，不用单页响应替换完整步骤。

`agent-pagination.browser.mjs` 在旧代码上无法读到第 120 条，15 秒后超时。
修复后覆盖 350 条分段、450ms 分页 RTT、3.8 秒慢页、后页 503、恢复重试、刷新，
以及 320–1440px 布局。分页失败时验证第 120 条仍保留且半途读到的数据不会提前提交，
恢复后验证第 350 条可见。测试使用隔离账号和模拟 PocketBase，不修改线上记录。
